# 数据质量规则

- 适用范围：dwd、dws 层所有表
- 版本：v1.5（2026-09-20 更新）
- 维护部门：数据平台组
- 要点：质量规则写在方案每张表的 `quality_rules` 里、逐行判断：主键不为空（drop）、金额不为负（warn）、关键维度不为空（warn）、明细数量为正（drop）；唯一性用主键表达，口径要排除的数据在转换逻辑里过滤。

## 怎么写

质量规则写在方案每张目标表的 `quality_rules` 里，平台按规则生成 Databricks 的数据期望（expectations），管道代码里不用再写。

- 规则逐行判断：条件是一个 Spark SQL 布尔表达式，只能用这一行的列，不能用 `count`、`sum` 等聚合函数。
- 规则名用小写英文加下划线，说明它检查什么，如 `order_id_not_null`、`sales_amount_non_negative`。
- 违反时的处理 `on_violation`：

| 取值 | 含义 | 用在什么地方 |
| --- | --- | --- |
| `drop` | 丢弃这一行，并记录丢了多少行 | 这一行明显无法使用 |
| `warn` | 保留这一行，记录违反的行数 | 需要关注、但不影响使用 |
| `fail` | 整个更新失败 | 只用于数据错了会造成严重后果的情况，dev 阶段不用 |

## 必须有的规则

| 规则 | 写法 | 处理 |
| --- | --- | --- |
| 主键不能为空 | `order_id IS NOT NULL` | `drop` |
| 金额不能为负 | `sales_amount >= 0` | `warn` |
| 关键维度不能为空 | `city IS NOT NULL AND member_level IS NOT NULL` | `warn` |
| 明细数量为正 | `quantity > 0` | `drop` |

## 唯一性

“汇总表每个维度组合只能有一行”“明细表一行一条明细”这类唯一性要求用主键 `primary_key` 表达，不要写成质量规则（逐行判断写不出唯一性）。

## 业务口径和质量规则的分工

按口径要排除的数据（取消订单、测试账号）在转换逻辑里过滤掉，不要写成质量规则去丢弃。质量规则用来处理“本不该出现”的数据问题，比如数量为 0 或负数的明细是录入错误，用 `quantity > 0` 规则 `drop`；违反的行数会出现在运行报告里，方便追查源头。

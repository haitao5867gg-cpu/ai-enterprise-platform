# 媒体处理连接器

落在哪一层：**连接器（MCP）+ 平台的媒体库和调用工具节点**。

- 连接器 `connectors/media` 封装 ffmpeg，提供三个工具：探测、抽帧、渲染。渲染一次做完截取、铺底、拼接、烧字幕、混音和导出。
- 平台这边加两件事。一是上传的素材由它探测，从 `processing` 变成 `ready`，并带上缩略图。二是调用工具节点能把工具产出的文件存进绑定的媒体库，就是运行产出的素材（`source.kind: run`）。
- 任何编排应用都这样用，应用里只写节点和参数。第一个用它的是教练做视频（转写配音 → 排镜头 → 找素材 → 渲染）。

媒体库本身见 [media.md](media.md)，长任务见 [connector-jobs.md](connector-jobs.md)。

## 连接器

`connectors/media` 是独立的 uv 包。它和别的连接器一样是 MCP Streamable HTTP，本地编排里叫 `connector-media`，端口 8008，地址 `http://connector-media:8008/mcp`。镜像里装了 ffmpeg（带 libass）和思源黑体（Noto Sans CJK）。

- 平台编排（`docker-compose.yml`）带它，启动时登记成工具服务「媒体处理」（`kind: mcp`，走 `AEP_DEFAULT_DATASOURCES`）。
- 运行包（`infra/runtime/compose.yml`）也带它。流程用到「媒体处理」时，按清单里的 `datasource_id` 绑定这个地址，规则同别的工具服务（[runtime.md](runtime.md)）。

### 文件在哪

连接器和平台挂同一个媒体卷，挂载点是 `AEP_MEDIA_DIR`（默认 `/data/media`）。工具的参数和结果里的路径都是**相对这个目录的媒体路径**，有两种：

- **库里的文件**：`<library_id>/<item_id>/<文件名>`，就是素材摘要里的 `path`。连接器只读。
- **工作文件**：`_work/<任务>/<文件名>`，连接器产出的东西（帧、缩略图、成片）都写在这里。连接器删掉 24 小时（`AEP_MEDIA_WORK_HOURS`）以前的工作文件。要留下的成片由平台移进媒体库，见下面「产出的文件存进媒体库」。

连接器以非 root 用户（65532）运行。它只能写 `_work`，启动时把这个目录建好并交给自己，库里的目录它只能读。

参数里的绝对路径、带 `..` 的路径、软链接，还有解析后跑出媒体目录的路径，一律报工具错误「路径不对：…」。文件不存在时报「文件不存在：…」。

连接器能读所有库的文件，不分应用。哪个应用能用哪个库，由平台在绑定、素材输入和存库这几处管（[media.md](media.md)“绑定”），连接器不再管。所以它只在内部网络上，不对外开端口。

### 素材参数（Source）

参数里要一个文件的地方（`source`）可以写下面三种之一，这样能直接整段引用上一个节点的产出：

- 媒体路径（字符串）。
- 带 `path` 的对象：素材摘要（开始节点的素材输入、存库后的文件）。
- 文件引用 `{"aep_file": {"path": "…"}}`：上一个工具的产出，还没存库的。

### 文件引用

工具产出的每个文件，在结果里都写成一个只有 `aep_file` 键的对象：

```jsonc
{"aep_file": {"path": "_work/j_7f3a/成片.mp4", "name": "成片.mp4"}}   // name 可选，不写用路径最后一段
```

平台靠这个形状认出结果里的文件（见下面「产出的文件存进媒体库」），所以别的连接器产出文件时也照这个写。

### 工具

#### `probe`：探测

参数：`{"source": Source, "thumbnail": false}`。普通工具，最多 `AEP_MEDIA_CHECK_SECONDS`（默认 20）秒，在平台的工具调用超时（30 秒）之前返回；超了报「探测超过 20 秒还没完：文件读得太慢」。

```jsonc
{"kind": "video" | "audio" | "image",          // 按扩展名，同媒体库
 "duration_seconds": 12.4 | null,              // 图片为 null
 "width": 720 | null, "height": 1280 | null,   // 按显示的样子（手机竖拍带旋转标记的已经转过来，宽像素的按显示宽度）；音频为 null
 "orientation": "portrait" | "landscape" | "square" | null,
 "fps": 29.97 | null,
 "has_video": true, "has_audio": true,
 "video_codec": "h264" | null, "audio_codec": "aac" | null,
 "size_bytes": 26312704,
 "thumbnail": {"aep_file": {…}} | null}         // thumbnail 为 true 且有画面时：长边 480 像素的 JPG，取第 1 秒（不到 1 秒的取中间）
```

扩展名是视频，文件里却没有画面，报「不是有效的视频：…」；音频没有声音、图片读不出来，同理报「不是有效的音频」「不是有效的图片」。

#### `frames`：抽帧

给看图模型看画面用。参数如下：

```jsonc
{"source": Source,                 // 视频或图片；图片只出一帧
 "at": [1.0, 3.5] | null,          // 在这几个时间点取，秒
 "every_seconds": 2 | null,        // 或者每隔几秒取一帧，从 0 开始
 "count": 6,                       // 都没写时均匀取几帧（各段的中间），1–100
 "max_frames": 30,                 // 上限，1–100，多出来的丢掉
 "width": 512}                     // 帧的宽，64–1920，高按比例
```

结果如下：

```jsonc
{"duration_seconds": 12.4,
 "frames": [{"time": 1.0, "width": 512, "height": 910, "image": {"aep_file": {…}}}]}
```

- 超过时长的时间点丢掉。
- 通常几秒就做完：20 秒内做完时返回已经 `done` 的任务（带 `result`），超过 20 秒交回还在跑的任务。抽帧出错（比如给的是音频）直接报工具错误。

#### `render`：渲染

把一组镜头按顺序接起来，铺上配音、背景音乐和字幕，导出一个 MP4。总是交回长任务。参数如下：

```jsonc
{"width": 1080, "height": 1920,    // 输出画面，240–3840 的偶数；默认竖屏 1080×1920
 "fps": 30,                        // 15–60
 "background": "#000000",          // 画面没铺满时的底色
 "clips": [                        // 1–300 个镜头，首尾相接，硬切
   {"source": Source,              // 视频或图片
    "start": 0,                    // 从素材第几秒开始，默认 0；图片不用写
    "duration": 2.5,               // 这个镜头多长，0.2–600 秒；图片必填，视频不写就到素材结尾
    "fit": "contain" | "cover" | "blur",
                                   // contain（默认）：整个画面放进去，空出的地方是底色，横屏素材在竖屏里就是上下黑边
                                   // cover：铺满，裁掉多出来的部分；blur：整个画面放进去，空出的地方用这个画面放大模糊铺底
    "focus": [0.5, 0.5],           // cover 时保留哪一块，横、竖各 0–1，默认正中
    "volume": 0}                   // 素材自己的声音，0–2，默认 0（静音）
 ],
 "audio": [                        // 0–10 条音轨，叠在整段视频上（配音、背景音乐）
   {"source": Source,              // 音频，或带声音的视频
    "at": 0,                       // 从成片第几秒开始放，默认 0
    "start": 0,                    // 从这条音轨第几秒开始取，默认 0
    "duration": null,              // 取多长，默认到音轨结尾或成片结尾
    "volume": 1.0,                 // 0–2
    "loop": false,                 // true：放完从头再放，直到成片结尾（背景音乐）
    "fade_in": 0, "fade_out": 0}   // 淡入、淡出秒数，0–10
 ],
 "subtitles": {                    // 可选，烧进画面
   "cues": [{"start": 0.0, "end": 2.1, "text": "冬天减脂比夏天难吗"}],   // 0–2000 条，按成片的时间，每条最多 200 字
   "style": {"size": 60,           // 字号，按 1080 宽的像素算，别的宽度等比缩放；10–200
             "color": "#FFFFFF", "outline": 3, "outline_color": "#000000",
             "y": 0.82,            // 字幕中心在画面高度的哪里，0–1
             "max_chars": 16,      // 一行最多几个字，超了自动换行（按标点和空格优先断）
             "bold": false}},
 "duration": null,                 // 成片多长，默认等于所有镜头加起来
 "output": {"name": "成片.mp4",     // 要是 .mp4
            "quality": "standard" | "high" | "draft"}}   // 默认 standard
```

默认值照教练剪片的样子定：横屏素材放在竖屏中间、上下黑边，白色细描边的小字幕在 82% 高度，硬切。

结果如下：

```jsonc
{"video": {"aep_file": {"path": "_work/j_7f3a/成片.mp4", "name": "成片.mp4"}},
 "duration_seconds": 52.0, "width": 1080, "height": 1920, "size_bytes": 31457280}
```

- **画面形状**：先按显示的样子摆正（旋转标记、宽像素都算上），再按 `fit` 放进成片，抽帧和缩略图也一样。
- **时间**：每个镜头按帧对齐，接起来的总长和各镜头时长之和最多差一帧，字幕和配音不会越接越偏。
- **素材不够长**：视频从 `start` 截 `duration` 截不满时，差 0.5 秒以内就停在最后一帧补齐；差更多报「第 3 个镜头：素材只有 4.2 秒，从 3.0 秒起截不出 2.5 秒」。
- **音轨**：比成片长的截掉，短的就到它结束为止（`loop` 除外）。
- **字幕**：落在成片时长以外的字幕丢掉。
- **编码**：H.264（yuv420p）加 AAC 48 kHz，元数据放在文件开头（手机上边下边播）。`draft` 快、文件大一点、画质差一点，`high` 慢、画质更好。
- **进度**：按镜头报，`message` 是「渲染第 3 个镜头，共 12 个」，最后一步是「合成成片」（拼接镜头、混音）。字幕在渲染每个镜头时就烧进去了。
- **缓存**：渲染好的镜头按参数和素材文件缓存 24 小时。只换一个镜头再渲染时，别的镜头不重做，所以「换镜头」很快。
- **限制**：成片最长 `AEP_MEDIA_MAX_SECONDS`（默认 600）秒，超了报错。同时只渲染 `AEP_MEDIA_MAX_JOBS`（默认 1）个任务，别的排队，排队时 `status` 是 `queued`，`message` 是「排队中，前面还有 2 个」（在渲染的也算）。
- **参数不合格**：交任务之前就检查（包括每个素材能不能用），报工具错误，原因指到第几个镜头、哪一项，比如「第 2 个镜头：图片要写 duration」「第 1 条音轨：要是音频或带声音的视频」。素材同时探测 4 个，整个检查最多 `AEP_MEDIA_CHECK_SECONDS`（默认 20）秒，好在平台的工具调用超时（30 秒）之前交回任务；超了报「检查素材超过 20 秒还没完：素材太多，或者有文件读得太慢」。检查期间同一个键又来了，也只开一个任务。
- **`duration`**：比所有镜头加起来短时，从那里截断；长时，最后一个镜头放完选中的那段后停在它的最后一帧补齐，不接着放素材后面的画面（图片就是放得更久）。

### 长任务

按 [connector-jobs.md](connector-jobs.md) 实现 `aep_job_status` 和 `aep_job_cancel`，同一个任务键接上原来的任务。

做完的任务和结果写在 `_work/.jobs/` 里，连接器重启后还认得。重启时还没做完的任务记为失败：「连接器重启了，任务没做完」。运行重试会用同一个键开新任务，已经渲染好的镜头从缓存里拿。

取消时停掉 ffmpeg，删掉这个任务没做完的文件。

### 设置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `AEP_MEDIA_DIR` | `/data/media` | 媒体卷的挂载点，和平台一样 |
| `AEP_MEDIA_MCP_HOST` / `AEP_MEDIA_MCP_PORT` | `0.0.0.0` / `8008` | |
| `AEP_MEDIA_MAX_JOBS` | 1 | 同时渲染几个任务 |
| `AEP_MEDIA_CHECK_SECONDS` | 20 | 探测、渲染前检查素材最多几秒，要比平台的工具调用超时短 |
| `AEP_MEDIA_MAX_SECONDS` | 600 | 成片最长几秒 |
| `AEP_MEDIA_WORK_HOURS` | 24 | 工作文件、缓存和任务记录留多久 |
| `AEP_MEDIA_FFMPEG_THREADS` | 0 | 每个 ffmpeg 进程的线程数，0 让 ffmpeg 自己定 |

## 平台这边

### 上传后探测

平台设了 `AEP_MEDIA_CONNECTOR_URL`（平台编排和运行包里都是 `http://connector-media:8008/mcp`）时，上传的素材（平台页面和 `/v1` 都算）先是 `processing`。平台后台按上传先后挨个调 `probe`（视频和图片带 `thumbnail: true`），写上 `duration_seconds`、`width`、`height`（`orientation` 由宽高得出）和缩略图，变成 `ready`。

- `probe` 报工具错误：素材变成 `error`，`error` 是「探测失败：」加上原因，比如「探测失败：不是有效的视频：…」。
- 连不上连接器：素材留在 `processing`，过一分钟再试。平台重启后接着探测没做完的素材。
- 没设 `AEP_MEDIA_CONNECTOR_URL`：同现在，上传后直接 `ready`，没有时长和宽高。
- 还在 `processing` 的素材不能做运行的素材输入（422，[media.md](media.md)“素材输入”）。外部页面经 `/v1` 上传后，轮询素材详情，等到 `ready` 再发起运行，一般一两秒。

### 缩略图

`MediaItem` 加 `has_thumbnail`（true 或 false）。下载缩略图用：

- `GET /media-libraries/{library_id}/items/{item_id}/thumbnail` → JPG；没有时 404「这个素材没有缩略图」。
- `/v1/apps/{app}/media-libraries/{library_id}/items/{item_id}/thumbnail`：规则同 `/v1` 下载素材。

缩略图在媒体卷上这个库的 `_thumbnails/<item_id>.jpg`，和素材一起删。页面上的视频卡片先显示缩略图，点开再播放。

### 产出的文件存进媒体库

调用工具节点加一个可选设置：

```jsonc
"save_media": {"library": "uuid",        // 存进哪个库：要以 write 绑定在 media.libraries 里
               "description": "",        // 可选，最多 500 字符，可以引用变量
               "tags": []}               // 可选，规则同素材标签
```

保存时检查：库不是以 `write` 绑定的，报「存进的媒体库要以“写”权限绑定到应用」，`loc` 指到 `save_media.library`。

应用绑定了媒体库时，调用工具节点的设置里有「产出的文件存进媒体库」：从以“写”绑定的库里选一个（选「不存」就去掉这项设置），填素材说明和标签。

运行时，工具（或长任务）的结果里每个文件引用 `{"aep_file": …}`，平台都按顺序存进这个库：

1. 检查路径要在 `_work/` 下面，是普通文件，不是软链接；扩展名、大小和库里的素材上限同上传。最多 20 个。
2. 在原地逐个探测（同上传后探测）：有一个不是能用的音视频或图片，整批不存。连不上连接器时不探测，照原样存。
3. 都通过后，把文件和缩略图移进库里，建素材，直接是 `ready`：`source` 是 `{"kind": "run", "run_id": "<这次运行>"}`，`uploaded_by` 是 null，名称用引用的 `name`。
4. 结果里的文件引用换成素材摘要，和素材输入的产出一样（`item_id`、`library_id`、`name`、`kind`、`duration_seconds`、`width`、`height`、`path`）。后面的节点拿到的是库里的文件，`/v1` 的 `files` 和运行页也列出它。

任何一步不过，节点以 `tool_error` 失败：「存进媒体库失败：文件「成片.mp4」：…」（探测不过时是「…：探测失败：不是有效的视频：没有画面」）。这一批一个都不存，节点的 `on_error` 照常生效。

同一次运行里同一个工作文件只存一次：节点重新执行（平台重启后接上原来的任务）时，结果里还是那个文件，就用已经存好的素材，不会建第二个。

存的时候出了错（库满了、数据库断了、运行被取消），已经移进库里的文件放回 `_work`，节点重新执行时再存。数据库其实已经写进了素材、只是回答丢了的时候，重新执行时找到这个素材，把文件补进库里，再探测一次（补回缩略图）。

没设 `save_media` 时，结果原样交给后面的节点，文件引用还指着工作文件，24 小时后被删。抽的帧一般这样用。

单节点测试不是运行，不存库，结果原样。

智能体节点调工具时，结果里的文件引用不存库，原样给模型看。

## 本地编排和运行包

- `docker-compose.yml` 和 `infra/runtime/compose.yml` 加 `connector-media`，挂 `media-data` 卷。平台编排的 `AEP_DEFAULT_DATASOURCES` 加「媒体处理」。
- 两边的 API 都设了 `AEP_MEDIA_CONNECTOR_URL`。这个地址和文件连接器一样总是允许（[datasources.md](datasources.md)“白名单”），所以运行包不用改 `AEP_CONNECTOR_HOSTS` 就能绑定它。

## 测试

连接器测试（`connectors/media/tests`）用真的 ffmpeg 生成几秒的测试视频、音频和图片：

- 探测：竖拍带旋转标记的视频、没有声音的视频、音频、图片、坏文件、不存在的文件，以及跑出目录的路径和软链接。
- 抽帧：`at`、`every_seconds`、`count`、`max_frames`，超出时长的时间点丢掉。
- 渲染三种 `fit`：输出的宽高、帧率、时长；首尾相接后总长误差在一帧以内；图片镜头；素材差 0.5 秒以内补齐，差多了报错；音轨的 `at`、`loop`、截断；字幕烧进去（检查画面变了）；成片超长报错。
- 长任务：交回任务后查到做完，同一个键接上原来的任务，取消后 ffmpeg 停下、文件删掉，排队和排队时的说明，重启后认得做完的任务，没做完的记为失败；换一个镜头再渲染时别的镜头走缓存；过期的工作文件、缓存和任务记录被清掉。

后端测试（`backend/tests`）用假媒体连接器（`tests/fake_connector.py`，不跑 ffmpeg）：

- 上传后探测：`processing` 变成 `ready`，写上时长和宽高；探测报错时变成 `error`；连不上时留在 `processing`，恢复后探测完；没配连接器时直接 `ready`。
- 缩略图：平台和 `/v1` 都能下载，没有时 404，删素材时一起删。
- `save_media`：保存时检查库的权限；结果里的引用换成素材摘要，`source.kind` 为 `run`；路径不在 `_work`、软链接、扩展名不对、空文件、超过大小、超过个数、有一个探测不过时整批不存，节点以 `tool_error` 失败；节点重新执行不重复存；存的时候出错或被取消，文件放回 `_work`，素材其实已经记下时重新执行把文件补进库里、再探测；单节点测试不存；存的时候连不上连接器就不探测照原样存；`/v1` 的 `files` 和 `GET /runs/{id}/media` 列出存进的素材。

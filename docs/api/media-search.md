# 按描述找素材

流程要从媒体库里挑出“拍到这句话讲的事”的素材，靠的是每个素材的画面描述。这份契约加两件事：

1. **自动描述**：媒体库可以打开「自动描述」，上传的视频和图片探测完后，平台抽几帧交给能看图的模型，写一句画面描述。人可以改，改过的不再被覆盖。
2. **检索素材节点** `media_search`：编排应用的节点按词、类型和标签从绑定的库里取出能用的素材，带描述，交给后面的节点（排镜头的模型、逐项处理……）。

落在哪一层：**平台资源（媒体库）+ 节点类型**。任何应用都能用；第一个用的是教练做视频：教练上传自己拍的素材，AI 写好描述，排镜头时模型对着描述挑素材，看图模型再核对。

媒体库本身见 [media.md](media.md)，抽帧见 [media-processing.md](media-processing.md)，看图模型见 [vision.md](vision.md)。

## 自动描述

### 库的设置

`MediaLibrary` 加 `describe`：

```jsonc
"describe": null | {
  "model": "company-vision",          // 必填，标了「能看图」的对话模型别名
  "hint": "健身教练自己拍的训练和饮食素材"   // 可选，最多 200 字符：库里是什么、描述时注意什么
}
```

- `POST /media-libraries`、`PATCH /media-libraries/{library_id}` 可以带 `describe`。新建时写 `null` 和不写一样，不自动描述；PATCH 写 `null` 关掉，不写不变。别的字段都不能是 `null`。
- 检查（422，`detail` 是一句话，同媒体库别的接口）：网关上没有这个模型「网关上没有模型「x」」；不是对话模型或没标能看图「模型「x」没标能看图，换一个能看图的模型」；`hint` 超长等格式问题同别的字段。连不上网关时不查模型，照样保存。
- 打开或换了模型后，库里还没描述的素材（见下面「哪些素材会被描述」）在后台一个个补上。

### 素材的字段

`MediaItem` 加两个字段：

```jsonc
"description_by": "person" | "model" | null,   // 现在的描述是谁写的；null：还没人写过
"describe_error": null | "写描述失败：……"         // 模型没写成的原因
```

- 人写的都算 `person`：上传时带了不空的 `description`（平台页面、`/v1`）、PATCH 把 `description` 改成了别的（改成空也算；和原来一样不算，所以只改标签时模型写的描述还算模型的）、调用工具节点 `save_media` 写了不空的说明。
- 模型写的是 `model`。
- 以前存下的素材是 `null`。

### 哪些素材会被描述

同时满足这几条的素材，平台在后台按上传先后一个个描述：

- 所在的库打开了 `describe`；
- `status` 是 `ready`，`kind` 是 `video` 或 `image`；
- `description` 是空的，`description_by` 是 `null`，`describe_error` 是 `null`。

所以人写过、改过（包括清空）的描述不会被模型覆盖；描述失败的不会反复重试，要重写时点「AI 重写」（见下）。

### 怎么描述

1. 用媒体处理连接器的 `frames` 抽帧：视频均匀取 4 帧（`count: 4`），图片取它自己；宽 512 像素。
2. 把帧按顺序作为图片，连同一段文字发给库设置的模型，经 `aep.llm`：
   - 系统提示（平台固定）：只写画面里看得到的东西：谁（几个人、男女、大致年龄，看不到脸写“不露脸”）、在做什么、在哪里、景别和角度、画面上有没有字幕或文字。一句中文，不超过 80 个字，不推测，不评价。
   - 用户消息：库的 `hint`（有的话）、文件名、时长、横竖屏，后面跟着各帧。
3. 回答去掉首尾空白和引号，换行换成空格，最多 500 个字符，写进 `description`，`description_by` 记 `model`。
   - 写之前再看一眼：这期间人已经写了描述（`description` 不空或 `description_by` 不是 `null`）就不写。

失败时：

- 连不上媒体处理连接器或网关：这个素材先放着，一分钟后再试。
- 抽帧报错、模型报错或回答是空的：记 `describe_error`，比如「写描述失败：模型报错：…」。
- 数据外发策略不允许：按平台默认的策略（[projects.md](projects.md)「数据外发策略」，`AEP_ALLOWED_MODELS`、`AEP_DATA_MEDIA`）检查模型和「图片」，不允许时不发请求，记 `describe_error`「写描述失败：平台不允许把图片发给模型」或「写描述失败：平台只允许用模型 …」。
- 没设媒体处理连接器（`AEP_MEDIA_CONNECTOR_URL`）时不描述，素材原样等着。

模型调用照常记进调用记录（[models.md](models.md)「调用记录」），不属于任何运行。

### AI 重写

`POST /media-libraries/{library_id}/items/{item_id}/describe` → 202 `MediaItem`：清空描述（`description` 为空，`description_by`、`describe_error` 为 `null`），后台马上重写。

- 库没打开自动描述：409「这个媒体库没有打开自动描述」。
- 不是视频或图片：422「只能给视频和图片写描述」。
- 搭建者角色才能调（同别的写操作）。`/v1` 不开放这个接口。

### 页面

- 媒体库页的库设置里加「自动描述」：开关、选模型（只列能看图的对话模型）、填说明。
- 素材卡片：模型写的描述旁标「AI 写的」；在等着描述时显示「AI 正在写描述」；失败时显示原因。打开了自动描述的库，视频和图片的卡片上有「AI 重写」。

## 检索素材节点 `media_search`

```jsonc
{"id": "footage", "type": "media_search", "title": "教练素材",
 "library": "uuid",            // 必填，media.libraries 里绑定的库，读或写都行
 "query": "",                  // 可选，最多 200 字符，可以引用变量；空格分开的每个词都要出现在名称、描述或标签里（不分大小写）；空的不按词筛
 "kinds": ["video", "image"],  // 可选，1–3 个不重复的 video、audio、image，不写为都要
 "tags": [],                   // 可选，最多 20 个；要带着这些标签（全部）
 "limit": 50}                  // 可选，1–200，不写为 50
```

只取能用的素材：`status` 为 `ready`、`usable` 为 `true`。新的在前。

产出：

| 字段 | 内容 |
| --- | --- |
| `items` | 素材列表，每项是素材摘要（同开始节点的素材输入：`item_id`、`library_id`、`name`、`kind`、`duration_seconds`、`width`、`height`、`path`）再加 `orientation`、`description`、`tags`、`source` |
| `count` | `items` 有几项 |
| `total` | 符合条件的一共几个（可能比 `limit` 多） |

- 整段引用 `{{footage.items}}` 写在提示词里是 JSON，模型能看到每个素材的描述和 `item_id`、`path`；交给媒体处理工具时每项本身就是素材参数（带 `path` 的对象）。
- 无分支，可以设 `on_error`。

### 检查和失败

保存时（`loc` 指到节点里的键）：

- `library` 没写或不在 `media.libraries` 里：「要选一个绑定到应用的媒体库」。
- `query` 不是文字或超过 200 字符：「搜索词最多 200 个字符」。
- `kinds` 不对：「素材类型只能是 video、audio、image」；`tags` 不对：「标签最多 20 个，每个 1–20 个字」；`limit` 不在 1–200：「最多取几个要在 1–200 之间」。

运行时：库已经被删了，节点以 `input_error` 失败：「媒体库不见了：…」。找不到素材不算失败，`items` 为 `[]`。

单节点试跑：可以，按草稿里的设置查库。

### 页面和 mock

- 编辑页「添加节点」在「工具」下有「检索素材」。设置表单：从绑定的库里选一个（没绑定库时提示先在应用设置里绑定）、搜索词（可以插变量）、素材类型、标签、最多取几个。
- mock（`AEP_MOCK_RUNS`）：返回两个示例素材。

## `/v1` 和运行包

- `/v1` 的素材接口返回的 `MediaItem` 带上 `description_by`、`describe_error`；上传、PATCH 的规则同平台（人写的记 `person`）。
- 运行包：库的 `describe` 在运行包自己的媒体库上设（装包时建的库默认不打开），用运行包自己网关上的看图模型。运行要求清单不变。

## 测试

- 自动描述：打开后 `ready` 的视频和图片被描述（抽帧参数、发给模型的图片和文字、`description_by` 为 `model`）；人写过或清空过的、`describe_error` 不空的、音频、没打开的库都不碰；描述期间人改了就不覆盖；抽帧报错、模型报错、空回答记 `describe_error`；连不上连接器时稍后再试；外发策略不允许时不发请求；「AI 重写」清空后重写，没打开 409，音频 422；库设置的模型检查。
- 检索素材节点：保存检查各条；按词、类型、标签、`limit` 取，只取 `ready` 且 `usable` 的；`total`；库被删时 `input_error`；单节点试跑；运行要求清单和导出的 `requires` 带上绑定的库（已有规则）。
